# Пункт 2: памятка по порядку вызовов

## 1. Создание контекста

`NewCipherContext` проверяет параметры → применяет `WithWorkers` / `WithDelta` → подготавливает IV и Delta → вызывает `cipher.SetKey` → возвращает `CipherContext`.

На этом этапе горутины не запускаются. Контекст хранит шифр и настройки.

## 2. Шифрование

```text
Encrypt(ctx, data)
  → launch(ctx, data, false)
      → копирует data
      → создаёт канал результата
      → запускает горутину:
          process
            → проверка отмены через ctx.Err()
            → addPadding
            → transform
                → обработка блоков по выбранному режиму
                → block → cipher.EncryptBlock / cipher.DecryptBlock
          → отправка CipherResult{Data, Err} в канал
          → закрытие канала
      → возвращает канал, не дожидаясь обработки
```

## 3. Расшифрование

```text
Decrypt(ctx, data)
  → launch(ctx, data, true)
      → копирует data, создаёт канал, запускает горутину:
          process
            → проверка отмены
            → проверка кратности длины размеру блока
            → transform → block → конкретный шифр
            → removePadding
          → отправка результата и закрытие канала
      → возвращает канал
```

`block(..., false)` вызывает `EncryptBlock`, `block(..., true)` — `DecryptBlock`.
CFB, OFB, CTR и Random Delta используют `EncryptBlock` даже при расшифровании: шифр создаёт гамму, которая накладывается через XOR.

```go
ch := c.Encrypt(ctx, data) // Операция запущена; можно делать другую работу.
result := <-ch            // Ожидание результата, если он ещё не готов.
// Проверить result.Err перед использованием result.Data.
```

## 4. Где параллельность

В `launch` вся операция выполняется в отдельной горутине. Дополнительно `transform` может распределить блоки между работниками через `parallelBlocks`.

| Режим | Шифрование блоков | Расшифрование блоков |
|---|---|---|
| ECB | Параллельно | Параллельно |
| CBC | Последовательно | Параллельно |
| PCBC | Последовательно | Последовательно |
| CFB | Последовательно | Параллельно |
| OFB | Последовательно | Последовательно |
| CTR | Параллельно | Параллельно |
| Random Delta | Параллельно | Параллельно |

```text
parallelBlocks
  → создаёт дочерний контекст с отменой
  → запускает workers горутин-работников
  → отправляет номера блоков в канал jobs
      → свободный работник получает index
      → вызывает operation(index), переданную из transform
      → записывает блок в его участок output
      → ждёт следующего номера
  → закрывает jobs
  → group.Wait(): ждёт завершения всех работников
  → возвращает первую ошибку, ошибку отмены или nil
```

При первой ошибке `sync.Once` сохраняет её и вызывает `cancel()`. Раздача прекращается после обнаружения отмены; уже начатые вызовы шифра завершаются. Порядок завершения блоков произвольный, но каждый записывается на своё место по индексу.

В последовательной ветке `transform` используется обычный `for` и состояние `feedback`, изначально равное IV.

## 5. Другие способы вызова

- `EncryptInto` / `DecryptInto` → `into` → `launch` → ожидание результата → запись в `*destination` → ошибка или `nil` в канал завершения. Читать `destination` можно после получения сигнала завершения.
- `EncryptFile` / `DecryptFile` → `file` запускает горутину → `processFile` читает весь файл → вызывает `process` → записывает временный файл → переименовывает его в выходной → ошибка или `nil` в канал завершения.
