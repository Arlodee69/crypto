# Пункт 6 — DEAL

Реализация в [deal.go](deal.go) использует сеть Фейстеля из пункта 3 и собственный DES из пункта 4.

| Параметр | Значение |
|---|---|
| Размер полного блока | 16 байтов (128 бит) |
| Размер половины | 8 байтов — один блок DES |
| Ключ 16 или 24 байта | 6 раундов |
| Ключ 32 байта | 8 раундов |
| Раундовая функция | `F(R, Kᵢ) = DES.EncryptBlock(R)` с ключом `Kᵢ` |

## Что вызывается

```text
NewDEALCipher
  → создаёт объект без установленного ключа

SetKey
  → выбирает число раундов по длине ключа
  → NewFeistelCipher(16, rounds, DEALKeyExpander{}, DESAdapter{})
  → network.SetKey
      → DEALKeyExpander.ExpandKey
      → сохраняет копии раундовых ключей

EncryptBlock (ровно 16 байтов)
  → network.EncryptBlock
      → делит блок на L и R по 8 байтов
      → каждый раунд: (L, R) = (R, L XOR DESAdapter.Transform(R, Kᵢ))
          → адаптер создаёт DES → SetKey(Kᵢ) → EncryptBlock(R)
      → возвращает R || L после последнего раунда

DecryptBlock
  → тот же алгоритм сети с ключами в обратном порядке
```

Снаружи DEAL дополнительных перестановок IP/FP нет. Внутри каждого вызова DES его собственные перестановки выполняются как обычно.

Адаптер не хранит общий изменяемый DES: у каждого вызова свой экземпляр. Поэтому блоки можно обрабатывать параллельно через контекст пункта 2. Это простой учебный вариант; DES-ключи внутри адаптера подготавливаются заново при каждом вызове.

## Генерация ключей

Исходный ключ делится на `s = 2, 3 или 4` части по 8 байтов. Для шифрования при генерации используется фиксированный DES-ключ `0123456789ABCDEF`.

```text
previous = 0000000000000000
Для i = 0 … rounds−1:
  input = часть исходного ключа с индексом i mod s
  Если i >= s: input XOR= константа[i−s]
  Kᵢ = DES_fixed(input XOR previous)
  previous = Kᵢ
```

Константы по порядку: `8000000000000000`, `4000000000000000`, `2000000000000000`, `1000000000000000` (hex). Получаем 6 или 8 ключей по 8 байтов. Их биты чётности игнорируются внутренним DES; при генерации цепочки сохраняются все 64 бита.

Описание структуры и расписания: [Kelsey, Schneier, раздел 2](https://www.schneier.com/wp-content/uploads/2016/02/paper-deal.pdf), [Lucks, раздел 2](https://citeseerx.ist.psu.edu/document?doi=2c417e66b47e36c7b723715609fc76980c48b04c&repid=rep1&type=pdf). В этой реализации явно используется соглашение сети из пункта 3: F от правой половины, выход `R || L`.

## Использование

```go
cipher := point6.NewDEALCipher()
err := cipher.SetKey([]byte("0123456789abcdef")) // 16 байтов.
// Проверить err.
encrypted, err := cipher.EncryptBlock([]byte("abcdefghijklmnop"))
// Проверить err.
restored, err := cipher.DecryptBlock(encrypted)
```

Для длинных сообщений передайте `point6.NewDEALCipher()` в `point2.NewCipherContext`: режимы и набивки уже поддерживают блок 16 байтов. Новый ключ можно установить до обработки; ошибка SetKey сохраняет предыдущий ключ. Одновременно менять ключ и обрабатывать блоки нельзя.

Из каталога `lab1`:

```powershell
go run ./point_7/cmd/deal_demo
```

Демонстрация и тесты DEAL находятся в [пункте 7](../point_7/README.md). Пункт 6 содержит только реализацию алгоритма.
