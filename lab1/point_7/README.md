# Пункт 7 — DEAL: массивы и файлы

Из `crypto/lab1`:

```sh
go run ./point_7/cmd/deal_demo
```

В `cmd/deal_demo/main.go` явно выполняются два шага:

```go
point5.TestBytes(ctx, point6.NewDEALCipher(), key, os.Stdout)
point5.TestFiles(ctx, point6.NewDEALCipher(), key, dir, flag.Args(), os.Stdout)
```

Это те же проверки, что у DES. Они принимают готовый шифр и ключ; фабрики и промежуточные `Run`/`RunWithKey` удалены. Массивы проверяются в `point_5/demo.go`, файлы — в `point_5/files.go`.

Проверяются все 7 режимов и 4 набивки. Восемь массивов имеют длины 0, 1, 15, 16, 17, 31, 64, 1025 байт. Создаются шесть файлов-образцов: текст, JPEG, WAV, Y4M, исходник Go и бинарный файл с концевыми нулями. Любое несовпадение завершает команду с ошибкой.

По умолчанию ключ DEAL-128: `0123456789abcdef` (16 ASCII-байтов). Свои файлы передаются аргументами:

```sh
go run ./point_7/cmd/deal_demo -out ./demo_output "/путь/example.txt"
```

DEAL-192 и DEAL-256 выбираются через hex-ключ:

```sh
go run ./point_7/cmd/deal_demo -key 000102030405060708090a0b0c0d0e0f1011121314151617
go run ./point_7/cmd/deal_demo -key 000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f
```

Результаты: `demo_output/deal-demo-*`. В `inputs` — образцы, в `<режим>/<набивка>` — `*.enc`, в `decrypted` — восстановленные файлы с исходными расширениями. Для каждого сообщения создаётся контекст со случайным IV; шифрование и дешифрование выполняются с тем же контекстом. Ключ, IV и Delta отдельно не сохраняются.

Файлы обрабатываются и сравниваются порциями по 64 КиБ. Для Zeros исходная длина хранится в заголовке файла `ZR01` + 8 байт длины, поэтому концевые нули сохраняются. Старые файлы Zeros без заголовка нужно зашифровать заново.

Автоматические тесты разделены на массивы и файлы, оба проверяют ключи 128, 192 и 256 бит:

```sh
go test ./point_7 -v
go test ./point_7 -run '^TestDEALBytes$' -v
go test ./point_7 -run '^TestDEALFiles$' -v
```
