# Лабораторная работа №2 — основы криптографии, Go

Реализация всех четырёх заданий из [2627 МАИ ОК 2.pdf](../tasks/2627%20МАИ%20ОК%202.pdf).
Отдельный модуль `cryptography/lab2`, Go 1.20 или новее, без внешних зависимостей.

## Запуск

Простая демонстрация только пункта 1 с вызовами функций и выводом результатов:

```sh
cd lab2
go run ./cmd/point1_demo
```

Код: [cmd/point1_demo/main.go](cmd/point1_demo/main.go). В нём можно менять
аргументы вызовов; каждый блок подписан по соответствующему требованию задания.

Из корня рабочего каталога:

```sh
cd crypto/lab2
go test ./...
go vet ./...
go run ./cmd/demo
```

Демонстрация последовательно выполняет четыре пункта, проверяет арифметические
контрольные значения, восстановление данных и результаты атак. Полный результат
одного запуска сохранён в [demo_run.log](demo_run.log).

Параметры демонстрации:

```sh
go run ./cmd/demo -test miller-rabin -bits 128 -attack-bits 32 -confidence 0.999999999 -timeout 30s
go run ./cmd/demo -test solovay-strassen -bits 128
go run ./cmd/demo -test fermat -bits 16
```

`-bits` — длина **каждого проверяемого кандидата p и q**, как в задании.
Длина модуля `n=pq` составляет `2*bits-1` или `2*bits` бит.
`-test` выбирает тест для защищённого генератора RSA; пункт 2 всегда демонстрирует
все три теста. Генератор уязвимых ключей использует Миллера–Рабина и отдельный
параметр `-attack-bits`. Генерация и тесты поддерживают отмену через контекст.

Go не поддерживает классы, наследование и объявления типов внутри других типов.
Поэтому буквальная форма `nested enum`, `nested service` и абстрактного класса
из PDF заменена следующими конструкциями Go:

- `TestKind` и `KeyGenerator` объявлены в пакете `point3`; объект `Service`
  содержит собственный закрытый объект генератора. Все три параметра
  конструктора сервиса делегируются конструктору генератора.
- Три конкретных теста встраивают `*Template`. Его общий метод `Test` задаёт
  порядок действий и вызывает заменяемое поведение `Iteration.Check`.
  Добавление нового теста не требует изменения шаблонного метода.

Готовые реализации RSA и тестов простоты в рабочем коде не используются.
`math/big` нужен для хранения длинных чисел и базовых арифметических операций;
`big.Int.GCD`, `Exp`, `ModInverse`, `Sqrt`, `ProbablyPrime`, `big.Jacobi` в
реализации сервисов не вызываются. Соответствующие алгоритмы написаны вручную.
`crypto/rand.Reader` поставляет только случайные байты. Выбор случайных целых
выполнен собственным rejection sampling без смещения от взятия по модулю.
В тестах некоторые функции `math/big` используются только как независимые эталоны.

## Пункт 1: арифметика

`point1.Service{}` не хранит состояние, готов к работе без конструктора и не
изменяет переданные числа. Параметры типа `*big.Int` должны быть ненулевыми
указателями; недопустимые математические значения возвращают ошибку там,
где она предусмотрена сигнатурой метода.

- Все три НОД принимают отрицательные числа и нули; `gcd(0,0)=0`.
  `ExtendedGCD` возвращает `g >= 0`, `x`, `y`, удовлетворяющие `ax+by=g`.
- `ModPow` использует двоичное возведение в степень; показатель неотрицателен,
  модуль положителен. Поддерживаются отрицательное основание, показатель 0
  и модуль 1. Обратный элемент вычисляется через собственный `ExtendedGCD`.
- `Jacobi` использует квадратичный закон взаимности; знаменатель положителен
  и нечётен, включая 1. Для `Legendre` вызывающий обязан передать **простое** `p`;
  символ вычисляется критерием Эйлера, `p=2` обрабатывается отдельно.
  Сам вычислитель символа не запускает тест простоты.
- `TotientDefinition` считает взаимно простые числа;
  `TotientFactorization` применяет `φ(n)=n∏(1−1/p)`;
  `TotientFourier` непосредственно суммирует
  `gcd(k,n)·cos(2πk/n)` для `k=1..n`, с компенсацией ошибки сложения.
  ДПФ ограничено диапазоном `1..1_000_000` из-за численной точности и стоимости
  линейного перебора. Результат округляется с проверкой близости к целому.
- `Carmichael` находит НОК значений для простых степеней. Для `2^r`, `r>=3`,
  используется `λ(2^r)=2^(r−2)`; для остальных простых степеней — значение `φ`.
  Приняты `φ(1)=λ(1)=1`; для неположительного `n` возвращается ошибка.

Пробное деление в `Factorize` предназначено для небольших учебных чисел.
В RSA факторизация модуля для вычисления `φ` не нужна: генератор уже знает `p,q`.
Целочисленные квадратный и четвёртый корни также реализованы самостоятельно.

## Пункт 2: вероятность и шаблонный метод

```go
test := point2.NewMillerRabin(nil) // nil выбирает crypto/rand.Reader
ok, err := test.Test(context.Background(), big.NewInt(65537), 0.999999999)
```

Все тесты принимают `confidence` в `[0.5,1)`; `NaN`, бесконечности и 1 отвергаются.
Вероятность трактуется стандартно для теста составности: для **фиксированного
составного n** вероятность ошибочного принятия не превышает `1-confidence`.
Это не апостериорная вероятность простоты уже принятого числа; её нельзя
вывести без сведений о распределении кандидатов.

Основания независимы и равномерны в `[1,n−1]`; основания, не взаимно простые с `n`,
не исключаются. Простые числа всегда проходят все итерации.

- Соловей–Штрассен: `t` выбирается так, чтобы `2^(−t) <= 1-confidence`.
- Миллер–Рабин: `4^(−t) <= 1-confidence`.
- Ферма: обычная оценка `2^(−t)` для произвольного составного `n` неверна
  из-за чисел Кармайкла. Здесь используется более медленная гарантированная схема.
  Пусть `B=floor(sqrt(n))+1`, а `r` — минимальное целое с
  `2^(−r) <= 1-confidence`. Выполняется `B*r` итераций.

Обоснование последней оценки: наименьший простой делитель составного `n`
удовлетворяет `p<=sqrt(n)`. Доля оснований, кратных `p`, равна
`(n/p−1)/(n−1) >= 1/(p+1) >= 1/B`. Такие основания отвергаются по НОД.
Вероятность пропустить все свидетели за `B` итераций не больше
`(1−1/B)^B < 1/2`, а за `B*r` — меньше `2^(−r)`.
Это работает и для чисел Кармайкла, но требует порядка `sqrt(n)` итераций.
Поэтому демонстрация RSA с Ферма использует 16-битные множители; для больших
множителей используйте другой реализованный тест. `Rounds` позволяет заранее
узнать число итераций. Подсчёт степеней двойки выполнен точными рациональными
числами, чтобы округление `float64` не занизило число итераций.

Оценки ошибок и различие условных вероятностей сверены с
[Handbook of Applied Cryptography, глава 4, §§4.2 и 4.4](https://cacr.uwaterloo.ca/hac/about/chap4.pdf).

## Пункт 3: RSA

```go
service, err := point3.NewService(point3.MillerRabin, 0.999999999, 128)
if err != nil {
    return err
}
keys, err := service.GenerateKeys(context.Background())
if err != nil {
    return err
}
_ = keys // копия с n, e, d, p, q, phi и числом итераций Ферма
encrypted, err := service.Encrypt([]byte("Пример\x00\x00"))
if err != nil {
    return err
}
decrypted, err := service.Decrypt(encrypted)
if err != nil {
    return err
}
fmt.Printf("%q\n", decrypted)
```

В примерах подразумеваются импорты `context`, `fmt`, `math/big` и соответствующих
пакетов `cryptography/lab2/point_2`, `cryptography/lab2/point_3` по необходимости.

Конструктор проверяет параметры; первую и последующие пары создаёт `GenerateKeys`.
До первой генерации методы возвращают `ErrNoKey`. Ошибка или отмена новой
генерации сохраняет предыдущую пару. Возвращаемые ключи глубоко копируются.
Параллельные операции используют снимок ключа на всё сообщение; генерации
сериализованы. Между отдельными вызовами шифрования и дешифрования пользователь
должен сохранять ту же текущую пару ключей.

Генератор выбирает разные нечётные вероятно простые `p,q` заданной битовой длины,
фиксирует `e=65537`, вычисляет `φ(n)=(p−1)(q−1)` и `d=e⁻¹ mod φ(n)`.
При невзаимной простоте `e` и `φ(n)` кандидаты выбираются заново.

Для длины множителей `b` дополнительно проверяются:

1. Точное число неудачных итераций факторизации Ферма
   `T=(p+q)/2−ceil(sqrt(pq))` должно быть не меньше `2^floor(b/2)`.
   Таким образом исключаются близкие множители, дающие быстрый успех этой атаки.
2. `d >= 2^b > sqrt(n)`, что существенно превышает диапазон малых экспонент
   классической атаки Винера.
3. Реальный запуск `WienerService.Attack(e,n)` не должен восстанавливать ключ.

Факторизация Ферма математически всегда завершается; здесь под её
неприменимостью понимается исключение быстрого успеха с указанной нижней
границей работы. При `b=128` это минимум `2^64` неудачных итераций.
Малые значения `b` предназначены для демонстрации и тестирования.

`EncryptInteger` / `DecryptInteger` работают с числами в `[0,n)`.
Байтовые методы делят сообщение на блоки: целое открытого блока кодируется как
`0x01 || payload`; зашифрованные блоки записываются в big-endian фиксированной
длины. Это сохраняет начальные и конечные нули, пустой ввод и длину последнего
блока. При расшифровании проверяются длина, диапазон и формат блоков.
Это учебный RSA без OAEP и аутентификации; маркер `0x01` лишь задаёт формат,
а стойкость ключей к двум заданным атакам не делает схему шифрования прикладной.

## Пункт 4: атака Винера

```go
result, err := (point4.WienerService{}).Attack(big.NewInt(17993), big.NewInt(90581))
// После обработки err: result.Found=true, result.D=5, result.Phi=89964.
// result.Convergents содержит все вычисленные подходящие дроби для e/n.
```

Сервис строит цепную дробь для `e/n`, вычисляет подходящие дроби `k/d`, проверяет
делимость `ed−1` на `k` и получает кандидата `φ=(ed−1)/k`. Затем решает
`x²−(n−φ+1)x+n=0`: дискриминант должен быть точным квадратом, а корни —
разными целыми числами больше 1 с произведением `n`.
`Convergents` и `RecoverFactors` доступны как отдельные компоненты.

Результат содержит флаг успеха, `d`, `φ(n)`, `p,q` и **все** подходящие дроби,
включая `0/1`. При неудаче секретные параметры равны `nil`, коллекция дробей
сохраняется. Отсутствие результата само по себе не доказывает стойкость RSA.

`NewVulnerableGenerator(bits, confidence, nil)` создаёт повторно используемый
генератор заведомо уязвимых примеров. Он обеспечивает `p<q<2p`, выбирает `d>=3`
с `gcd(d,φ)=1` и `3d<floor(n^(1/4))`, вычисляет `e=d⁻¹ mod φ`, а перед возвратом
проверяет, что атака точно восстанавливает исходные `d` и `φ`.
Это удовлетворяет условию Винера `d<n^(1/4)/3`; описание атаки и условия сверены с
[Dan Boneh, Twenty Years of Attacks on the RSA Cryptosystem, §3](https://crypto.stanford.edu/~dabo/papers/RSA-survey.pdf).

## Проверки

```sh
go test ./point_1
go test ./point_2
go test ./point_3 ./point_4
go test -race -cover ./...
go vet ./...
```

Тесты используют фиксированные источники псевдослучайных байтов для повторяемости.
Проверяются отрицательные аргументы и нули, равенство Безу, большие числа,
квадратные корни около точных квадратов, квадратичные вычеты, три формулы Эйлера,
функция Кармайкла по определению, вероятностные границы на малых составных,
числа Кармайкла и псевдопростые, расширение шаблона, ошибки случайного источника,
отмена, все три варианта генератора RSA, известный вектор `65^17 mod 3233=2790`,
двоичные данные на границах блоков, некорректные шифротексты, владение ключами,
параллельные вызовы и восстановление сгенерированных уязвимых ключей.
